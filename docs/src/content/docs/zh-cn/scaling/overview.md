---
title: 规模扩展总览
description: 规模扩展阶段：在三档训练预算下，同时选择架构、参数量和训练 token 数。
---

排行榜回答的是一个问题：固定训练预算、模型大小按预算校准、token 数也固定时，哪种架构学得最好？规模扩展阶段问的是更大的问题：**在固定的训练预算下，架构家族、参数量和训练 token 数怎样组合，能得到最低的验证 BPB 和最高的 CORE？** 只有算力是固定的，每个家族都可以在参数量和 token 数之间取舍。

进展可以在观测站的 [Scaling 页面](https://interactive-active-ai.github.io/NextTransformer/#scaling)上查看：一张三维图展示所有已完成的运行（参数量、训练 token 数，以及 CORE 或验证 BPB，颜色表示家族），下方是计划中的阶梯。

## 三档预算

| 档位 | 训练 FLOPs | 批大小 | 作用 |
|---|---|---|---|
| T3 | 1.0 × 10²⁰ | 每次更新 2²⁰ tokens | 拟合：每个家族 5 个尺寸 |
| T4 | 2.3 × 10²⁰ | 每次更新 2²⁰ tokens | 拟合：每个家族 5 个尺寸；即 49B 对比协议的预算 |
| C200 | 4.88 × 10²¹ | 每次更新 2²¹ tokens | 检验：由 Dense 200B-token 参照训练确定 |

预算按每个输入 token 的理论训练 FLOPs 乘以输入 token 数计算（[口径](../protocol/#预算)）。在 T3 和 T4，每个家族训练 5 个尺寸，从“每个参数很多 token”到“每个参数很少 token”，每档预算画出一条有最低点的曲线。根据这些运行，我们预测每个家族在 C200 的最优尺寸及其验证 BPB 和 CORE，先登记预测，再在 C200 上训练预测的最优点。

## 架构家族

| 家族 | 尺寸规则 | 状态 |
|---|---|---|
| Dense | 宽度 = 64 × 层数，头维 128，FFN 为 4 倍宽度的 ReLU²，带 value embedding；即参照训练的骨干 | 开放认领 |
| MoE | Dense 骨干，第一层保留稠密 FFN，其余每层 256 个路由专家（选 8）加 1 个共享专家，每个专家宽度为 width/4 | 等待配方通过[稳定性门槛](../protocol/#架构家族) |

更多家族可以通过[社区贡献](../contribute/#新增架构家族)加入。

## 报告什么

- **每档预算：** 最终验证 BPB 和 CORE 随参数量的变化，每个家族一条曲线。
- **每个家族：** 计算最优的参数量、token 数和损失随预算的变化。
- **家族之间：** 算力等效增益，即 Dense 达到某家族的结果需要的算力，除以该家族实际使用的算力。
- **C200：** 已登记的预测与实测结果的对照。

## 文件在哪里

| 路径 | 内容 |
|---|---|
| `results/scaling/ladder.json` | 预算、家族，以及每一格的尺寸、token 数、状态和认领人 |
| `results/scaling/runs/` | 每个已完成运行一份记录，由 `python -m nexttransformer.scaling.export` 生成 |
| `evidence/forecasts/` | 已登记的预测及其结果 |
| `configs/scaling/` | 每个已训练格子的配置 |
| `nexttransformer/scaling/`、`launch/scaling/` | 适用于无共享文件系统节点的训练器及其启动脚本 |

Dense 参照训练（40 层、宽 2,560，在 4,096 上下文下训练 200B tokens）是 C200 的第一个点。规模扩展的记录不是排行榜条目，它们遵循自己的协议，见[规模扩展协议](../protocol/)。
