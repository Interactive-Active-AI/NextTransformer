这是规模扩展协议 `nextt-scale-4k-v1`。它独立于冻结的 49B [参考协议](../../protocol/overview/)，不改变后者的训练约定。机器可读的取值在 `results/scaling/ladder.json` 和 `nexttransformer/scaling/config.py` 中。

## 预算

一次运行的预算是它的理论训练 FLOPs：每个输入 token 的 FLOPs（来自 `nexttransformer.models.native.model.theoretical_training_flops`）乘以输入 token 数。对层数为 `L`、宽度为 `d`、上下文 `T = 4096`、词表 `V = 32768` 的 Dense 骨干，每个 token 为 `72·d²·L + 12·T·d·L + 6·d·V`，所有因果注意力对都计入。MoE 用激活参数代替 `12·d²·L`。

一格的 token 数等于所在档位的预算除以每 token 的 FLOPs，再取整到完整的更新步数；结果与预算相差不超过 1%。阶梯文件列出了每一格的 token 数，训练器的 `--dry-run` 会打印一份配置的训练计划。

| 档位 | 训练 FLOPs | 每次更新的 tokens |
|---|---|---|
| T3 | 1.0 × 10²⁰ | 1,048,576 |
| T4 | 2.3 × 10²⁰ | 1,048,576 |
| C200 | 4.88 × 10²¹ | 2,097,152 |

## 配方

每次运行都使用 Dense 参照训练的配方 `configs/scaling/dense_200b.json`，只改变模型尺寸、token 数和所在档位的批大小。

| 项目 | 取值 |
|---|---|
| 数据 | 锁定版本的 ClimbMix，共用的训练/验证划分，BOS best-fit 打包 |
| 分词器 | 锁定的 32,768 词表分词器 |
| 上下文 | 4,096 tokens |
| 优化器 | 矩阵用 Muon，嵌入层、输出层和标量用 AdamW；学习率按 √(批大小 / 524,288) 缩放，嵌入层和输出层的学习率还按 √(768 / 宽度) 缩放；Muon 的权重衰减按 nanochat 对所训练模型的规则 |
| 调度 | 40 步预热，之后恒定，最后 65% 线性衰减到峰值的 5% |
| 随机种子 | 每格第一次运行用 42 |
| 评测 | 每 1,000 步及结束时测验证 BPB；每 20,000 步及结束时测完整的 22 项 CORE；结束时在 20,971,520 个 token 上做一次最终 BPB |

修改配方即为新的协议版本；旧版本下训练的格子不与新版本混在同一次拟合中。

## 架构家族

一个家族是一个只有一个尺寸旋钮（层数）的骨干，加上一条由层数推出其余所有维度的规则。

- **Dense：** 宽度 = 64 × 层数，头维 128（头数 = 宽度 / 128），FFN 为 4 倍宽度的 ReLU²，隔层带 value embedding。
- **MoE：** Dense 骨干；第一层保留稠密 FFN，其余每层 256 个路由专家、选 8，加 1 个共享专家，每个专家宽度为 width / 4。

一个家族的格子要在配方通过**稳定性门槛**后才开放：在 T3 和 C200 规模上都训练至少 1,500 步，不出现负载塌缩（每层最热专家低于公平份额的 12 倍，各层均值低于 3），也不发散。MoE 目前处于等待状态。

## 评测

绘图和拟合使用一次运行的最终验证 BPB（来自最终 BPB 这一遍，在运行自身的 4,096 上下文下测得）和最终 CORE。49B 协议的验证 BPB 在 2,048 上下文下测得，不与规模扩展的运行比较。

## 拟合

1. 对每个家族，用该家族在 T3、T4 的全部运行以及已记录的 C200 运行拟合 `L(N, D) = E + A / N^α + B / D^β`，其中 `N` 是 block 参数量（MoE 用激活 block 参数量），`D` 是训练 token 数。
2. 分档检查：在 T3 内、T4 内分别对 `log N` 拟合抛物线找最低点，最低点必须落在 5 个尺寸之内。
3. 按上面的预算口径推出 C200 的计算最优 `N`、`D` 和损失，并按运行做 bootstrap 给出区间。
4. 报告每个家族相对 Dense 在 T3、T4 和 C200 的算力等效增益。

## 预测登记与 C200 检验

一个家族的第一次 C200 运行开始之前，至少要有一份针对它的预测合入 `evidence/forecasts/`（[格式](https://github.com/Interactive-Active-AI/NextTransformer/tree/main/evidence/forecasts)）：所用的记录、方法、预测的最优点，以及预测的验证 BPB 和 CORE 及其 90% 区间。任何人都可以登记。维护者随后按自己那份预测的最优点、取整到家族规则允许的最近尺寸进行训练，并把结果和每一份预测放在一起公布，无论预测是否成立。

## 记录

`python -m nexttransformer.scaling.export` 从运行目录生成 `results/scaling/runs/<id>.json`。未完成的运行、配置不一致的运行，或缺少计划中的验证或完整 CORE 评测的运行都会被拒绝。记录只保存科学数据，不写主机名、路径、设备和命令。记录不可修改。
